The short version

A portfolio with real engineering in it, undermined by unenforced quality gates

The strongest work here is genuinely strong. Revise runs 412 passing tests and gets Supabase row-level security exactly right, including the with check clause most people forget. Forq ships a real Content-Security-Policy with per-request nonces. Daily Debate authenticates and rate-limits every API route it exposes. No secret has ever been committed to any of the three repositories — every model API key is server-side only. That is not beginner work.

The problem is not capability, it is enforcement. Four of the thirteen apps have no tests and no CI at all, and those four are exactly where both serious security findings live. Three CI pipelines are configured in a way that means they can never pass — one has been failing on all 14 runs because of a YAML syntax error, one type-checks a codebase containing zero TypeScript files, and one cannot install because its lockfile is stale. The repository even ships its own smoke test that currently fails; it is not wired into CI, so nothing acts on it.

The gap between the best and worst project in this portfolio is wider than the gap between this portfolio and a professional one. Closing it is mostly a matter of applying the standards already demonstrated in Revise and Forq to the four apps that never received them.

Findings

Ranked by severity

Two findings expose real data. Five break pipelines in ways that mean a quality gate you believe is running is not running. The rest is hygiene.

Critical 01apps/meeting-recorder/web/src/app/api/

Meeting transcripts are readable and searchable by anyone who can reach the deployment

GET /api/search takes a query string, runs a regex against every meeting's title, summary and full transcript text in MongoDB, and returns up to 100 complete meeting documents. It performs no authentication of any kind. An empty query returns the 100 most recent meetings outright.

// src/app/api/search/route.ts — the entire handler
export async function GET(req: NextRequest) {
  const q = (req.nextUrl.searchParams.get("q") || "").trim();
  const col = await getMeetings();
  // no isAuthorized(req), no session, no ownership filter
  const docs = await col.find(filter).sort({ createdAt: -1 }).limit(100).toArray();
  return NextResponse.json({ meetings: docs.map(toMeeting), ... });
}

Three further routes are equally unprotected: GET /api/meetings/[id]/transcript, GET /api/benchmarks, and POST /api/meetings/[id]/chat — the last of which reads the transcript and calls the Anthropic API on every request, making it an uncapped billing channel as well as a disclosure one.

Compounding this, the shared-secret helper that guards the four routes which are protected fails open:

// src/lib/auth.ts
export function isAuthorized(req: NextRequest): boolean {
  const expected = optional("DESKTOP_API_KEY");
  if (!expected) return true; // open in local dev when unset
  return req.headers.get("x-api-key") === expected;
}

A missing environment variable in a production deploy therefore silently disables authentication on the remaining routes rather than failing the deploy. And src/lib/securityReview.ts — a static object presented as an audit record — asserts "Desktop uploads require x-api-key === DESKTOP_API_KEY; share page is readOnly; transcript PATCH is authenticated", which describes only the protected half and creates false confidence about the rest.

Fix: Add an ownership or workspace filter plus a session check to search, transcript, chat and benchmarks. Change isAuthorized to return false when DESKTOP_API_KEY is unset and gate the local-dev exception behind an explicit NODE_ENV !== "production" check. Delete securityReview.ts or regenerate it from the routes rather than by hand — a hand-written security attestation that drifts is worse than none.
Critical 02apps/mental-load-tracker/supabase/schema.sql

Noticed's row-level security grants every anon-key holder full access to every household

All three policies are unconditional, and the anon key ships in the browser bundle by design:

create policy "Anyone with the anon key can read households"
  on households for select using (true);

create policy "Anyone with the anon key can manage items"
  on items for all
  using (true)
  with check (true);

The schema comment argues this is acceptable because "access control relies on the code/household id being hard to guess". That defence does not hold: the first policy permits select * from households, which returns every join code in the table. Guessing is unnecessary — the codes are enumerable in one query. From there, for all using (true) on items permits reading, editing and deleting any household's entries.

The comment's closing advice — "Do not store sensitive data in this app" — is also in tension with the product, which exists to record domestic labour disputes between two partners.

Fix: The pattern you want already exists in this repo. Revise scopes every policy to auth.uid() with a matching with check; port that. If account-free join codes are a deliberate product decision, then at minimum drop the select policy on households so codes cannot be listed, scope items policies to a household_id supplied through a signed claim rather than true, and move writes behind a server route holding the service-role key.
High 03.github/workflows/rtk.yml:56

RTK's CI has never run — the workflow file has never parsed

Every RTK run in the recent history failed, 14 out of 14, and none of them produced a single job. The cause is a YAML flow-mapping error on the last line of the file:

        env: { NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }} }
                                                       ↑ closes the flow mapping early

$ python3 -c "import yaml; yaml.safe_load(open('.github/workflows/rtk.yml'))"
ParserError: while parsing a flow mapping, line 56, column 14
expected ',' or '}', but got '{'

Inside { }, YAML treats } as a structural terminator, so the closing braces of the ${{ … }} expression end the mapping. GitHub rejects the file before scheduling anything — which is why the runs are titled .github/workflows/rtk.yml rather than RTK, the giveaway that the name: key was never read.

The practical cost: the three-version Node matrix, the type-check, the 43 tests, all six benchmark harnesses and npm pack --dry-run have never gated a single commit. RTK is the app whose entire value proposition is measured token reduction, and its measurement harness has never run in CI.

Fix: Quote the expression — env: { NODE_AUTH_TOKEN: "${{ secrets.NPM_TOKEN }}" } — or expand to block style. Then add a workflow-lint step (actionlint) so the next syntax error fails loudly instead of silently.

The first is a true positive: apps/genetic-health was deleted on 9 August but is still listed in apps/registry.json and named in the root README. validate-registry.mjs is well written and exits 1 correctly — it simply has no caller.

The second is a false positive, and that matters more. check-links.mjs validates every markdown link as a filesystem path:

// scripts/check-links.mjs
const target = path.resolve(base, href);
if (!existsSync(target)) { console.error(`BROKEN ${file} -> ${href}`); }

For a root-relative Next.js route like /benchmarks, path.resolve discards the base and returns the filesystem root /benchmarks, which of course does not exist. Credit where due

What is genuinely well built

An audit that only lists faults misrepresents the work. These are things this portfolio does better than most codebases of comparable age.

Secrets discipline is flawless across all three repositories

A full scan of every tracked file for AWS keys, GitHub tokens, Anthropic keys, OpenAI keys and JWTs returned exactly one hit — a synthetic string inside apps/rtk/test/regression.test.js, which is the fixture for RTK's own redaction feature. Nine .env.example files are committed and not a single real .env. More importantly, the split is right: ANTHROPIC_API_KEY, GEMINI_API_KEY, GROQ_API_KEY, OPENAI_API_KEY and every service-role key are server-side only, and the sole browser-exposed credentials are Supabase anon keys, which are designed to be public. That mistake — a model API key behind a NEXT_PUBLIC_ prefix — is extremely common, and it is nowhere in these 185,000 lines.

Revise's row-level security is textbook

Rather than hand-writing ten near-identical policies and getting one wrong, the schema loops:

foreach target in array array['cards','review_logs','questions','attempts',
                              'mistakes','papers','planned_sessions',
                              'exam_dates','user_settings','streaks']
loop
  execute format('alter table public.%I enable row level security', target);
  execute format(
    'create policy %I on public.%I for all to authenticated
     using (user_id = auth.uid())
     with check (user_id = auth.uid())', target || '_owner', target);
end loop;

The with check clause is the part almost everyone omits, and omitting it lets a client rewrite user_id to another account's id on insert or update. The schema comment says so explicitly. Ten tables, no drift, no gaps.

Forq's Content-Security-Policy is stricter than most production apps ship

A per-request nonce with strict-dynamic, plus object-src 'none', frame-ancestors 'none', base-uri 'self' and form-action 'self' — generated in middleware and set on both the request and response headers. No unsafe-inline on scripts. Forq is also the only app that gates CI on npm audit --audit-level=high and the only one running Playwright end-to-end tests in CI, and it is the only app with zero dependency vulnerabilities. Those facts are connected.

Daily Debate's API surface is fully covered

All six routes authenticate; five of six rate-limit; the schema has RLS on all seven tables with eleven policies. For an app that spends money on model calls per request, that is the right shape, and it is the standard the other AI-calling apps should be held to.

arise-fitness is a properly finished open-source repository

Conventional commit messages, a maintained CHANGELOG.md, CONTRIBUTING / SECURITY / CODE_OF_CONDUCT, three issue templates and a PR template, a release workflow with generated notes, and a build that produces both a directory and an 80.7 KB single-file standalone. Tests, lint, format check and build all pass on a clean clone. It is also the only repository in the portfolio where the git history reads as deliberate work rather than a transcript of prompts — worth noting, because commit messages are part of what a reviewer judges.
